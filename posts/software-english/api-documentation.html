API 문서의 구조

API 문서를 효과적으로 읽기 위해서는 문서의 일반적인 구조를 이해하는 것이 중요합니다. 대부분의 API 문서는 다음과 같은 섹션들로 구성되어 있습니다.

주요 섹션과 영어 표현

1. Overview / Introduction

개요 / 소개

  • This API provides... - 이 API는 ~을 제공합니다
  • Allows you to... - ~할 수 있게 해줍니다
  • Enables developers to... - 개발자들이 ~할 수 있게 합니다
  • Designed for... - ~를 위해 설계되었습니다

2. Authentication

인증

  • Requires authentication - 인증이 필요합니다
  • API key / Access token - API 키 / 액세스 토큰
  • Bearer token - Bearer 토큰 (Authorization 헤더에 사용)
  • Credentials - 자격 증명
Example:
Authorization: Bearer YOUR_ACCESS_TOKEN

3. Endpoints

엔드포인트 (API 주소)

  • GET /users - Retrieve / Fetch users (사용자 조회)
  • POST /users - Create a new user (새 사용자 생성)
  • PUT /users/:id - Update user (사용자 수정)
  • DELETE /users/:id - Remove user (사용자 삭제)
  • PATCH /users/:id - Partially update (부분 수정)

4. Parameters

매개변수

Query Parameters (쿼리 파라미터)

GET /users?page=1&limit=10

- page (integer, optional): Page number for pagination
  기본값: 1
- limit (integer, optional): Number of results per page
  기본값: 10

Path Parameters (경로 파라미터)

GET /users/:id

- id (string, required): Unique identifier of the user
  사용자의 고유 식별자

Request Body (요청 본문)

POST /users

Body:
{
  "name": "string (required)",
  "email": "string (required)",
  "age": "integer (optional)"
}

5. 자주 사용되는 용어

  • Required - 필수
  • Optional - 선택 사항
  • Default - 기본값
  • Deprecated - 더 이상 사용되지 않음 (향후 제거 예정)
  • Legacy - 구버전, 레거시
  • Payload - 전송되는 데이터
  • Response - 응답

6. Response (응답)

Status Codes (상태 코드)

  • 200 OK - 성공
  • 201 Created - 생성됨
  • 400 Bad Request - 잘못된 요청
  • 401 Unauthorized - 인증되지 않음
  • 403 Forbidden - 권한 없음
  • 404 Not Found - 찾을 수 없음
  • 500 Internal Server Error - 서버 내부 오류

Response Body (응답 본문)

Success Response (200 OK):
{
  "id": "12345",
  "name": "John Doe",
  "email": "john@example.com",
  "created_at": "2025-10-27T10:30:00Z"
}

Error Response (400 Bad Request):
{
  "error": "Invalid email format",
  "message": "The provided email address is not valid",
  "status": 400
}

7. 문서에서 자주 보는 표현

  • Returns - ~을 반환합니다
  • Throws / Raises - ~예외를 발생시킵니다
  • Must be - ~이어야 합니다
  • Should be - ~이어야 합니다 (권장)
  • May be - ~일 수 있습니다
  • Note that - 주의: ~
  • For example / e.g. - 예를 들어
  • Such as - ~와 같은

문서 읽기 팁

  1. Overview부터 읽기: 전체적인 기능을 먼저 파악하세요.
  2. Examples 확인: 예제 코드를 보면 사용법을 빠르게 이해할 수 있습니다.
  3. Required vs Optional: 필수 파라미터와 선택 파라미터를 구분하세요.
  4. Error Handling: 어떤 오류가 발생할 수 있는지 미리 확인하세요.
  5. Rate Limits: API 호출 제한이 있는지 확인하세요.

정리

API 문서를 읽는 것은 처음에는 어려울 수 있지만, 구조와 자주 사용되는 표현에 익숙해지면 훨씬 쉬워집니다. 영어 문서를 자주 읽고 실제로 API를 사용해보면서 경험을 쌓는 것이 중요합니다.
